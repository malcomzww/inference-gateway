# inference-gateway

An OpenAI-shape API gateway — tiered routing with confidence escalation, exact
and semantic caching, per-tenant cost ledger, SSE streaming — built to answer
**one question: at what monthly request volume does self-hosting beat the
API?** The scope is deliberately narrow: every feature here exists either to
produce a realistic input to that cost model or to reduce one side of the
comparison. There is no dashboard, no admin UI, no provider marketplace and no
model registry, because none of those change the answer. This is a repo that is
narrow by design rather than thin by accident.

Two things it is honest about up front. **The self-hosted side of the breakeven
is modelled, not measured** — there is no GPU on the machine that produced
these results, so every throughput figure is a stated assumption carried in
code by a type named `ThroughputAssumption`. And **the semantic cache ships
disabled**, because measuring its false-hit rate is what this repo did instead
of assuming it worked.

## The answer

Against a **mid-tier** hosted model (~$2.50/$10.00 per M tokens), at a mix of
500 prompt + 200 completion tokens per request:

| self-host config (assumed) | crossover | can it serve that? |
|---|---|---|
| 1×A10G-class, 8B, $1.00/hr @ 50% util | **224,615 req/month** (~308/hr) | yes — ceiling is 2.63M |
| 1×A100-class, 70B, $3.50/hr @ 50% util | **786,154 req/month** (~1,077/hr) | yes — ceiling is 1.64M |

Against a **small** hosted model (~$0.15/$0.60 per M tokens), **self-hosting
never pays off** in any configuration modelled here — the crossover volume
(3.7M–13.1M req/month) sits *above* what that hardware can physically serve, so
you would need more replicas to reach the volume that justifies the first one,
and each replica pushes the crossover further away.

**The counter-intuitive finding: the crossover is invariant to throughput.**
Fixed monthly cost divided by per-request API cost has no throughput term. A
GPU twice as fast does not halve the volume at which self-hosting wins — it
only raises the ceiling on whether that volume is reachable at all. Verified
across a 16× throughput sweep and asserted in the generating script.

That is a convenient result, because throughput is the one input here nobody
measured. What *does* move the crossover is the API price you are replacing,
the GPU hourly rate, and your cache hit rate — all things you can look up or
measure rather than assume.

Full tables, sensitivity analysis and stated assumptions: **[`results/breakeven.md`](results/breakeven.md)**.

## Why this exists

The interesting failure in an LLM gateway is not a 500 — it is a semantic cache
returning a confident, fluent, *wrong* answer that raises no error and appears
in no dashboard. So rather than assume a similarity threshold, I measured the
false-hit rate against a corpus of hard negatives (one-word entity swaps,
negation, unit reversals) and got a decisive result: separation AUC **0.031**
against 0.5 for random guessing, and a best-achievable gain of **0.00** across
all thresholds. The embedder ranks the pairs it must not merge *above* the
pairs it should. The tier ships disabled, and
[ADR 0001](docs/adr/0001-semantic-cache-false-hit-rate.md) records why.

## Quickstart

```bash
uv sync --extra dev
uv run pytest -q                              # 73 tests, no network, no API key
uv run python scripts/generate_results.py     # regenerates results/
uv run uvicorn inference_gateway.app:app --port 58014
```

```bash
curl -s localhost:58014/v1/chat/completions \
  -H 'X-Tenant-Id: acme' -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"What is the capital of France?"}]}'
```

The response is OpenAI-shaped with an extra namespaced `gateway` block, so an
OpenAI SDK parses it unchanged while a caller who wants to know what the request
cost can find out without a second round trip:

```json
"gateway": {"served_by": "upstream", "escalated": false,
            "confidence": 1.0, "cost_usd": 0.0000063}
```

Full stack (Postgres 55446, Redis 56393, gateway 58014):

```bash
docker compose up --build
```

**There is no API key in this repo and it never makes a live LLM call.** The
upstream is an `httpx.MockTransport` handler speaking the OpenAI shape, injected
at the transport layer so `llm-client-kit`'s real retry loop, deadlines and
connection pooling stay under test — only the socket is replaced. CI that
depends on a third party's availability and pricing is not CI.

## What's here

| module | what it does |
|---|---|
| `cost_model.py` | The breakeven arithmetic. `ThroughputAssumption` isolates every unmeasured input. |
| `cache.py` | Exact + semantic tiers, `separation_auc`, `measure_false_hit_rate`. |
| `routing.py` | Cheap-first cascade; charges for **both** calls on escalation. |
| `app.py` | FastAPI: DI, lifespan, SSE, idempotency, per-tenant rate limiting and ledger. |
| `pairs.py` | The 60-pair labelled corpus the cache measurement runs on. |
| `upstream.py` | The stub. |

Built on [`llm-client-kit`](../llm-client-kit): `CostLedger` does the money
arithmetic in `Decimal` with budget enforcement that raises. Retry, concurrency
and cost accounting are not reimplemented here.

### Details worth noting

- **Tenant isolation is structural.** Cache, ledger, rate limiter and
  idempotency store are all keyed by tenant. A cache shared across tenants is a
  data-leak channel disguised as an optimisation.
- **Escalated requests are billed for both calls.** Charging only the second
  understates a cascade by exactly the amount that makes cascades look better
  than they are. At the 17× price gap modelled here, the cascade only stops
  paying off above a **94%** escalation rate ([`results/routing.md`](results/routing.md)).
- **Streaming holds one chunk at a time** and checks `is_disconnected()`
  between chunks; a departed client stops generation but is still billed for
  tokens already produced upstream. Both paths are tested — the disconnect test
  drives the ASGI app directly, because `TestClient` always drains the body and
  so can never reach that branch.

## Limitations

Things this repo does **not** establish:

1. **Any real self-hosted throughput.** No GPU here. Every `tok/s`,
   utilisation and `$/hr` is an assumption from published benchmarks. The
   crossover volumes are modelled outputs, not measurements, and should be
   re-run with your own numbers before informing a purchase.
2. **That the semantic cache result generalises.** The 60-pair corpus is
   synthetic, adversarial and written by one person; the embedder is lexical,
   not learned. A real sentence encoder would likely score far better — this
   repo never ran one, so it claims nothing about how much.
3. **That escalation improves answer quality.** The default confidence signal
   is a documented **stand-in** that detects hedging and truncation. It is
   trivially gamed and cannot detect a confidently-stated wrong answer. This
   repo models what a cascade *costs* at a given escalation rate, never what it
   is worth.
4. **Multi-worker correctness.** Cache, ledger and idempotency store are
   in-process, so the Dockerfile pins one worker. Postgres and Redis are
   declared in compose as the seam for that work; they are not yet wired in,
   and `pytest` needs nothing running.
5. **Authentication.** Tenant identity comes from an `X-Tenant-Id` header that
   any client can set. Real isolation needs a signed token whose claims cannot
   be spoofed. The header is honest about being a stand-in rather than implying
   auth the code does not perform.
6. **Real-provider behaviour.** Everything runs against a stub. Nothing here
   predicts any live provider's latency, error rates or token accounting.
