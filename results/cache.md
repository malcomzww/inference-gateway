# Semantic cache: the measured false-hit rate

Generated by `python scripts/generate_results.py`. Do not edit by hand.

> **Measured, but on synthetic data.** The corpus is
> 60 hand-written prompt pairs (30 paraphrases,
> 30 hard negatives) in `src/inference_gateway/pairs.py`, scored
> by a deterministic hashing embedder — not a learned sentence
> encoder. These are real measurements of a real component, and they
> generalise to no production workload. The transferable part is the
> method and the decision rule, not the numbers.

## Inputs

- Corpus: 30 equivalent + 30 non-equivalent pairs, fixed order
- Embedder: `HashingEmbedder(dim=256, ngram=4)`, deterministic
- Seed: none needed — no randomness anywhere in this measurement
- Reproduce: `python scripts/generate_results.py`
- Raw per-pair scores: `results/cache-raw.md` (gitignored)

## Threshold sweep

A *false hit* is a non-equivalent pair served from cache: a confident,
fluent, wrong answer that raises no error anywhere. A *false miss* is
only a wasted API call. The two are not symmetric, which is why they
are reported separately rather than as one accuracy figure.

| threshold | false-hit rate | true-hit rate | false hits | true hits |
|---|---|---|---|---|
| 0.50 | 97% | 37% | 29 | 11 |
| 0.60 | 97% | 23% | 29 | 7 |
| 0.70 | 90% | 7% | 27 | 2 |
| 0.75 | 77% | 3% | 23 | 1 |
| 0.80 | 60% | 0% | 18 | 0 |
| 0.85 | 37% | 0% | 11 | 0 |
| 0.90 | 13% | 0% | 4 | 0 |
| 0.92 | 7% | 0% | 2 | 0 |
| 0.95 | 0% | 0% | 0 | 0 |
| 0.98 | 0% | 0% | 0 | 0 |

**There is no usable row in that table.** Every threshold with a
non-zero true-hit rate also has a false-hit rate above 20%; every
threshold with an acceptable false-hit rate never hits at all. This
script asserts that no row is both safe and useful.

## The diagnostic that explains it

**Separation AUC = 0.031** — the probability that an equivalent
pair scores above a non-equivalent one. 1.0 is perfect, 0.5 is
coin-flipping, and this is **far below 0.5**, meaning the ranking is
*inverted*: the embedder systematically scores the pairs it must not
merge above the pairs it should.

**Best achievable `true-hit − false-hit` gain = 0.00** 
(at threshold 1.00). No threshold beats never caching.

The mechanism is that this embedder measures *lexical* overlap, and
the two classes differ in exactly the wrong direction:

- A hard negative changes **one word** — "Python 3.11" to "Python
  3.12", "Austria" to "Australia", "encrypt" to "decrypt" — so
  it stays lexically almost identical while the correct answer changes
  completely.
- A paraphrase changes **most words** — "How do I merge two
  dictionaries?" to "What's the way to combine two dicts?" — so it
  looks lexically distant while meaning the same thing.

Surface similarity and semantic equivalence are anti-correlated on
this corpus. That is not a threshold that needs tuning; it is an
embedder that cannot do the job at any setting.

## Consequence

**The semantic tier ships disabled** (`semantic_enabled=False`). The
exact-match tier, which cannot be wrong, stays on. See
`docs/adr/0001-semantic-cache-false-hit-rate.md`.

The code path is kept rather than deleted: it is what the measurement
runs against, and swapping in a real sentence encoder is a
one-argument change for anyone who re-measures and gets an AUC that
justifies turning it on.

## Limitations

- **Synthetic corpus, 60 pairs.** Adversarially constructed, so the
  false-hit rates are deliberately pessimistic. A real workload has a
  different and unknown mix of near-misses.
- **Lexical embedder, not a learned one.** Chosen so CI can measure
  this on every commit with no model download and no network. A real
  sentence encoder would likely score far better — this repo does not
  establish by how much, because it never ran one.
- Pairs were written by the same person who chose the negatives'
  categories, so the corpus reflects one view of what a hard case is.
